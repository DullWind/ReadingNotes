以下是这份研学计划里每个阶段的完整要求（导读 + 四个实战阶段）。这些要求来自宣讲材料、通关指南和会议纪要中的细节，其中“任务—交付物—考点”这三层分别对应实际的过程考核  。

 

前置导读（Phase 0）：理论全景与思维导图｜7 天上限

这是正式报名的唯一硬核准入凭证，不通过就无法进入第一阶段 。

必读范围（不要求通读全书，只精读以下章节）

- RTR4 Ch2 图形渲染管线：全章精读，掌握应用阶段、几何处理、光栅化、像素处理这四个阶段的工业界定义
- RTR4 Ch3 GPU 架构（3.1~3.2 节）：固定管线→分立着色单元→统一着色器架构（Unified Shader）的演化与指令分发
- RTR4 Ch4 Transforms（4.1~4.4 节）：模型变换、视口变换与空间变换的数学物理直觉
- 辅助查阅（不作主读）：《Unity Shader 入门精要》第 2、4 章、LearnOpenGL-CN 坐标系统与延迟着色、Forward/Deferred/Forward+ 对比文

需要建立的四个基本认知模型：CPU-GPU 协同（CPU 如何准备数据并向 Command Buffer 派发绘制指令、GPU 如何多核并行）；空间变换的物理直觉（模型→世界→观察→裁剪→屏幕）；渲染路径演进取舍（G-Buffer 与光源计算开销）；GPU 硬件架构演进 。

交付物：《个人理解的渲染管线数据流全景思维导图》，须梳理 CPU-GPU 交互链路、空间变换体系、渲染路径差异 。

规范底线：严禁用网络截图拼凑、严禁整包搬运现成内容；允许用 AI 做局部疑难答疑与公式推导，但整体逻辑必须本人透彻理解、工程思维自洽 。提交格式为 PDF，也可以用 XMind 或图片格式，提交给罗方静；导图质量与本人对学习的真实投入会被综合评估，评审通过后才会组建第一阶段研学班、开启每周专家答疑 。

 

第一阶段：纯 C# CPU 软光栅｜2 个月上限

学习目标：在空白 Unity 工程里，不使用 MeshRenderer、不使用 GPU Shader、不调用引擎封装的变换矩阵 API，纯用 C# 在 CPU 上实现现代光栅化流水线，把三维顶点投影并着色到一张  Texture2D  上 。

四步演进，每步独立交付工程与思路文档（不允许直接套用现成代码或 AI 整包代码） ：

1. Step 1 几何变换：手写 4×4 矩阵数据结构与矩阵乘法；推导并编码 Model、View 变换，以及基于 FOV/Aspect/Near/Far 的透视投影矩阵；手动完成透视除法并映射到 NDC。交付「变换模块代码包 + 《透视投影与除法数学推导及代码实现说明》」。硬核考点：透视除法中齐次分量  w = -z  的推导机制及执行时序，为什么必须在视锥裁剪后、屏幕映射前做 。
2. Step 2 光栅化：计算三角形屏幕空间 2D 包围盒；手写重心坐标判定像素中心与三角形内外关系；基于重心坐标完成法线与 UV 插值。交付「单三角形线框与平铺填充工程 + 包围盒判定与重心坐标插值实现思路」。考点：透视校正插值——在屏幕空间直接对 UV 做 2D 线性插值会失真，为何插值前属性与深度必须先除以  w  。
3. Step 3 深度消隐：分配  float[] depthBuffer  数组，在片元着色前做 Z-Buffer 比较与写回，正确处理多物体前后穿插遮挡。交付「多物体遮挡正确的 Texture2D 渲染工程 + 深度测试比对算法说明」。考点：非线性深度精度衰减的根因、前后空间遮挡判断的严密性 。
4. Step 4 材质光照：纯 CPU 计算 Ambient、Lambert 漫反射、Blinn-Phong 高光，手写纹理采样器完成 UV 寻址。交付「带基础材质光照的 3D 软渲染工程 + 逐片元光照计算注释」。考点：非等比缩放下法线为何不能直接乘 M、必须乘逆转置矩阵 (M^{-1})^{T} 。

验收方式：导师走查代码时不只看最终成图，重点看三件事——架构解耦（数学向量库、投影变换、光栅化器、着色器模块职责边界清晰）、推导注释（重心坐标、投影矩阵等关键算法附完备数学注释）、步骤演进（严格提交四个 Step 的独立工程，杜绝直接套现成代码）；再做现场“技术攻防”答辩，随机抽检上述数学推导，无法自圆其说需重新思考  。

配套：每周 1 次专家定时答疑，可直接深入源码级推导走查。业务即时反哺：能秒级排查顶点与遮挡类 Bug 。

 

第二阶段：手写 Unity 最小 SRP 管线｜2 个月上限

学习目标：把第一阶段的 CPU 软光栅逻辑映射到现代可编程管线的调度机制，基于  UnityEngine.Rendering  底层接口从零手写一条支持视锥裁剪、渲染队列划分、不透明/半透明绘制、深度测试与混合的最小闭环管线，并手写配套 Unlit Shader 。

教材：Catlike Coding《Custom SRP》前两章（Custom Render Pipeline、Draw Calls）+ RTR4 第 3 章 GPU 状态机与批处理开销 。

必须掌握的架构链路： RenderPipelineAsset （配置）→  RenderPipeline （调度实例）→  CommandBuffer  打包 → Culling 与队列过滤 →  context.Submit()  执行；要能讲清  RenderPipelineAsset  与  RenderPipeline  的职责解耦、 ScriptableRenderContext  的指令缓存与延迟提交机制、 DrawingSettings/FilteringSettings/SortingSettings  如何划分不透明与半透明队列，并在 HLSL 里手写 MVP 变换、正确配置 ZWrite/ZTest/Blend  。

交付物硬指标：一个纯手写、可独立运行的空白 Unity SRP 工程（禁止 Fork 模板或引用现成 URP Package 代码）；场景含至少 3 个不同材质（不透明、半透明）、不同网格形状的 3D 物体，遮挡与混合状态完全正常；支持摄像机视锥体裁剪（CullingResults），视锥外物体不产生无效提交 。

验收方式：代码逐行审核 + 现场抽问，导师会直接改你的代码做破坏性验证，限时阐明推导依据，杜绝死记 API ：

- 指令时序：调  context.DrawRenderers  后画面为何没出来？强行省略  Submit()  会发生什么，底层如何发起实际派发与缓冲区刷新；
- 状态机异常注入：现场开半透明 ZWrite，或关不透明 ZTest，观察穿插闪烁，并结合第一阶段深度缓冲原理解释成因；
- 渲染次序逆转：把不透明排序改成“由后向前”，量化 Overdraw 增量，结合 GPU Early-Z 硬件剔除推导弹幕带宽与耗时影响 。

配套：每 2 周 1 次答疑，现场代码修改验证。业务反哺：彻底看透 URP 合批打断、DrawCall 暴增与渲染队列错乱的底层根因 。

 

第三阶段：画风自造与量产工具链｜4 个月上限

这一阶段才真正涉及 TA 中的美术部分（A）：自选美术风格、自研着色模型、搭交互原型，并把画风做成可量产的规范 。

理论主干：RTR4 第 9 章（辐射度量：Flux / Irradiance / Radiance 与渲染方程物理意义）、第 10 章 10.1（PBR 与 IBL、Cook-Torrance 微表面 D/F/G 项）、第 14 章 14.1~14.5（NPR 描边、阶梯色调 Ramp、各向异性材质） 。

参考架构：公司自研 LGRendering 工业级管线（含 URP/HDRP 核心特性实现），需向导师申请仓库 Guest 权限 。

画风分支（自选其一）：物理向 Cook-Torrance PBR（自研 D/F/G 项、环境反射），或风格向 NPR（Ramp 贴图采样、自适应描边、网点着色等） 。

特性扩展与交互（自选叠加）：在自己的管线基础上加后处理（Custom Post-Processing）、程序化植被扰动、Compute Shader 粒子等；场景必须具备 Gameplay 动态交互，如顶点扰动植被碰撞、动态溶解、受击闪白等机制 。

阴影的技术取舍：不强制实现实时阴影；若不用 Shadow Map，须从艺术风格与暗部补偿角度论证画面明暗层次如何自洽 。

量产工具链（这一阶段的差异化重点）：制定贴图 Channel Packing 通道打包规范与网格顶点色分配技术手册；开发 Unity Custom Material Inspector 材质面板或自动化资产检查脚本；输出美术技术规范文档，保证美术团队能标准化复现  。

交付物：① 可交互的场景 Gameplay Demo（带个人强烈风格、立体环境）；② 量产工具 + 美术技术规范文档 。

评审权重：画面表现力与自洽度 50%、技术取舍合理性 30%、工具化与协同思维 20%；评审会邀请美术同学共同参与，画风属主观维度（约半数权重），能互相说服、自洽说明设计逻辑即可，但客观渲染瑕疵不能拿“风格”当借口，必须修正  。

资产合规：可使用公开现成资产，不得擅自使用公司项目资产；操作与分享保密规范后续统一同步 。周期 4 个月，每 2 周 1 次答疑、自治性技术现场交流 。

 

第四阶段：Vulkan 逆向与芯片微架构极限调优｜2 个月上限

学习目标：从软件层穿透到驱动层与移动端硬件底层。研读《Vulkan Programming Guide》核心 API，但不要求从零用 Vulkan 搓一条完整管线——重点是理解 API 调用流程与调度顺序 。

抓帧剖析：用 RenderDoc（或 Snapdragon Profiler 等）对第三阶段场景做逆向抓帧，梳理实际生成的  VkRenderPass 、Pipeline（PSO）状态切换批次与 Pipeline Barrier 内存依赖分布 。

微架构机理优化：结合 GPU Warp/Wavefront 调度机制诊断片元着色器的分支分化（Divergence）开销；针对移动端 TBDR 架构分析 Tile Buffer 的 Load/Store 频次与显存带宽吞吐瓶颈；理论参考 RTR4 第 18、23 章（流水线优化与 GPU 硬件微架构） 。

必须量化的四类指标：DrawCall 批次、PSO 状态切换、GPU 单帧耗时、Overdraw 层数与 Early-Z 剔除率、显存带宽吞吐/TBDR Tile 读写 。

交付物：《Vulkan 视角管线剖析与全场景性能调优报告》+ 调优后工程；必须给出严谨的量化对比数据（前后对照）与微架构机理论证，不能只写“优化了、变快了” 。

配套：每 2 周 1 次答疑，针对瓶颈实施微架构调优；周期比第三阶段短，因为这一阶段偏客观、可验证  。业务反哺：能攻坚移动端复杂性能卡死（发热、掉帧、PSO 重建、带宽瓶颈） 。

 

五个阶段通用的规则

- AI 使用边界：各阶段都允许用 AI 答疑、生成局部代码或推导公式，但禁止让 AI 完成整包工程、直接搬运；考核核心是“你是否真的掌握了这个知识”，编码结果本身权重不高 。
- 技术栈：前三个阶段最终交付须基于 Unity，以匹配公司现有技术栈、确保能直接落地 。
- Deadline 机制：每个阶段都设有最晚截止时间，逾期未完成视为自然中止该阶段，不设行政惩罚；各阶段高度解耦，鼓励提前交付，有基础可直接往后推进 。
- 选拔意义：各阶段 Milestone 的完成深度、工程标准、代码质量是团队未来评定核心 TA 的关键依据，导师组对质量有一票否决权 。
