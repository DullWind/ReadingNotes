## 1. 产品愿景

木弦成风是一款面向尤克里里初学者的 Android 学习应用。它不以提供大量课程为首要目标，而是按“音乐基础—尤克里里基础—简单练习曲—目标歌曲”的顺序组织训练：

> 先帮助用户理解拍子、TAB 和基础动作，再完整、流畅地用尤克里里指弹《幻化成风》（《風になる》）。

核心价值是让零基础用户知道每一个音为什么这样弹、手指应该放在哪里，再把完整作品拆成每天可以完成的短训练。基础阶段使用自有练习数据、TAB、动画和节拍器；歌曲阶段再根据练习反馈动态调整内容、速度和复习频率。

### 目标用户

- 尤克里里零基础或初级用户
- 已能完成简单按弦，但无法完整演奏目标歌曲
- 每天可练习 10～30 分钟
- 需要明确指导“今天应该练什么”
- 希望使用自己合法取得的音频进行降速跟练

### 阶段性成功标准

用户最终能够：

1. 完成 G–C–E–A 调音，并以放松姿势发出清楚声音。
2. 理解一拍、4/4 拍、四分音符和八分音符，并跟随 60 BPM 保持稳定节拍。
3. 读懂 TAB 中的琴弦、品位、节奏和反复记号。
4. 独立按出 C、Am、F、G7 等基础和弦，并完成简单练习曲。
5. 分段完成目标谱面中的所有乐句。
6. 在慢速下连续演奏，不因局部错误完全中断。
7. 逐步提升到目标速度 120 BPM。
8. 完整、稳定且有基本强弱层次地演奏整曲。

## 6. 核心领域模型

### 歌曲包

歌曲包不是单个 PDF 或 MP3，而是一组可计算数据：

    SongPack
    ├─ 基本信息：标题、作者、调性、拍号、目标速度
    ├─ Arrangement：具体编曲版本
    ├─ Sections：小节、速度、技巧、和弦和教学重点
    ├─ ScoreEvents：音符、时值、弦号和品位（待实现）
    └─ AudioMarkers：音频时间点（待实现）

    FoundationCourse
    ├─ Lessons：概念、目标、练习和过关自检
    ├─ Exercises：速度、拍号与按时间排列的练习事件
    ├─ FrettedNotes：琴弦、品位、指法和音名
    └─ ChordShapes：和弦音位与按弦提示

同一首歌未来可以有初级弹唱版、High G 指弹版、Low G 指弹版和简化版。学习记录必须关联具体编曲版本，不能只关联歌曲标题。

### 用户进度

当前进度数据包括：

- 当前计划日期
- 当日已完成任务
- 已完成基础课 ID
- 历史练习结果
- 用户本机音频 URI 和名称
- 默认日练时长

每次练习结果包括：

- 段落 ID
- 完成时间
- 用户评分 1～3
- 本次 BPM
- 练习时长

增加字段时必须提供默认值或迁移，不能让旧数据导致应用启动失败。

## 7. 动态计划算法

实现位置：src/services/planner.ts

### 掌握度

每个段落使用最近 4 次练习：

    段落掌握度 = 评分表现 × 65% + 速度完成度 × 35%

- 评分表现：评分除以满分 3 后取平均。
- 速度完成度：历史最佳 BPM 除以段落目标 BPM，最高 100%。
- 掌握度只用于展示当前质量与速度，不再单独决定解锁。
- 进入下一段要求在该段目标 BPM 下累计 3 次“流畅完成”，且成功记录跨至少 2 个自然日。

这是首版可解释的巩固规则，不代表客观演奏准确率；跨日要求用于避免一次练习中连续点击评分就跳过整段。

### 建议速度

- 没有记录：使用段落起始 BPM。
- 流畅完成：提高 5 BPM，不超过目标速度。
- 需要加强：降低 5 BPM，不低于起始速度。
- 基本完成：保持当前速度。

### 每日计划

未完成基础课时默认四项：

1. 调音与放松检查，2 分钟。
2. 理解本课音乐概念，4 分钟。
3. 跟随 TAB、动画和节拍器完成基础练习，动态分配时长。
4. 回听和总结，2 分钟。

六节基础课完成后，歌曲阶段默认四项：

1. 调音与手指唤醒，3 分钟。
2. 当前技巧准备或昨日卡点修复，4 分钟。
3. 当前段落主练习，动态分配时长。
4. 慢速连接与收尾，3 分钟。

完整原曲只在练习速度达到 90 BPM 后开放；低速练习不得把 120 BPM 原曲强行拉到 0.5 倍速作为教学伴奏。

每项自动任务必须展示“为何安排”，保持计划可解释。

### 后续可加入的信号

- 连续成功次数
- 无中断演奏次数
- 实际练习时长
- 最近练习间隔
- 错误集中小节
- 节拍偏差
- 提速后表现下降幅度
- 主观疲劳或疼痛反馈

## 8. 曲谱内容生产流程

每增加一个编曲版本，需要：

1. 确认来源和使用权限。
2. 确认调性、拍号、目标速度和 High G/Low G。
3. 按音乐结构和技术难点划分段落。
4. 录入小节范围、和弦、技巧和速度。
5. 将 TAB 转换为结构化音符事件。
6. 在设备上验证谱面显示。
7. 使用合法音频标注段落时间点。
8. 验证降速、跳转、循环和同步。
9. 由真实演奏者确认指法和教学顺序。
10. 完成版权记录后发布。

建议的音符事件字段：

- id
- measure
- beat
- durationBeats
- string
- fret
- chord
- technique

不要把完整曲谱硬编码在页面组件中。歌曲内容应作为独立数据加载，使 UI、计划算法和内容可以分别迭代。

## 9. 音频和版权边界

- 不内置未经授权的原版音频、歌词或商业曲谱。
- 用户通过 Android 系统文件选择器导入合法音频。
- 导入文件只在本机使用，不上传服务器。
- 音乐平台加密缓存不能作为普通音频导入。
- 未来公开歌曲包必须取得授权，或使用公共领域和自制内容。
- 节拍器 `metronome-click.wav` 来自 qubodup/OpenGameArt，采用 CC0；来源与 SHA-256 记录在 `assets/audio/README.md`。
- 引入录音和云功能前必须更新隐私政策。

## 10. 视觉和交互规范

设计关键词：

- 温暖木质
- 安静、有鼓励感
- 信息明确
- 每次只突出一个主要动作
- 像私人音乐教练，不像任务管理器

当前颜色：

- 背景：#F7F0E5
- 主木色：#9A6038
- 深木色：#5E3928
- 叶绿色：#61745A
- 强调色：#D9903D
- 主文字：#30251F

交互原则：

- 首页第一屏回答“今天练什么”。
- 训练页减少干扰。
- 速度同时显示 BPM 和百分比。
- 评分文案描述状态，不责备用户。
- 自动推荐必须展示原因。
- 关键触控区域不小于约 44 dp。
- 支持长中文文件名和系统字体缩放。

## 15. 架构约束

- App.tsx 当前是 MVP 入口；继续增长时拆到 src/screens。
- 动态计划规则只能放在 planner 或后续领域策略中。
- 歌曲内容只能放在 src/data 或歌曲包目录。
- 存储层必须提供默认值和迁移。
- UI 不直接依赖 PDF 文件结构。
- 本机音频 URI 不写入版本库或遥测。
- 新增依赖前确认 Expo SDK 和 Android 兼容性。
- 未验证的自动评分不能展示为确定性准确率。

M1 完成后建议拆分为 screens、components、hooks 和 domain 四层。拆分前先为计划算法建立单元测试，防止重构改变学习规则。
