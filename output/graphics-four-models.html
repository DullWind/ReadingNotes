01

CPU–GPU 协同：先组织，再并行

CPU 负责本帧的场景决策、资源和命令组织。GPU 从队列获取任务后，大量执行顶点、片元和计算线程。两者可以在不同帧上重叠工作。

三层关系

  1. 应用层：CPU 更新逻辑和相机，决定可见物体，准备网格、纹理、常量和管线状态。部分现代引擎也把剔除交给 GPU。
  2. API 层：以 Vulkan 为例，CPU 在 Command Buffer 中记录绑定状态、绘制、计算和拷贝命令，随后提交到设备队列。Draw Call 是其中的绘制操作，不等于一整条 Command Buffer。
  3. 硬件层：GPU 将相似着色调用组成 wave/warp 等执行组，跨许多执行单元并行，并在等待内存时切换到其他可运行组。
同步直觉

“已提交”不等于“已画完”。资源复用、CPU 读取 GPU 结果以及画面呈现都要满足同步关系。

物理直觉与计算顺序

  1. 模型 → 世界：模型矩阵把顶点从物体原点搬到场景。本例只平移 (+2,0,−6)。
  2. 世界 → 观察：观察矩阵是相机世界姿态的逆变换。相机向右走，物体在观察坐标里向左走。本例相机朝 −Z。
  3. 观察 → 裁剪：90° 视角、1:1 宽高比、近 1 远 10；投影得到 (x_c,y_c,z_c,w_c)，其中 w_c=−z_view。先按 −w≤x,y≤w，0≤z≤w 裁剪。
  4. 裁剪 → NDC → 屏幕：透视除法得到 (x/w,y/w,z/w)；再将 x、y 从 −1…1 映射到像素，屏幕 Y 向下。
最重要的区别

裁剪空间尚未做透视除法。远处物体变小的直接原因是投影后的 x、y 要除以随距离变化的 w。此例使用 Direct3D 风格的 NDC 深度 0–1；其他 API 约定可能不同。

模型边界

示意式：朴素前向 ≈ 覆盖层数 × 光源覆盖工作；延迟 ≈ 几何与 G-Buffer 成本 + 光源覆盖工作。真实结果还受早期深度测试、光源剔除、材质、阴影、带宽和硬件影响。增加物体数量不必然线性增加延迟光照成本。

04

GPU 架构演进：从专职车间到混合工厂

专用电路擅长重复且规则的工作；统一着色核心提供灵活的并行计算；缓存、调度与部分架构中的光追和矩阵单元针对新瓶颈补强。新模块并没有让光栅化、纹理采样和深度测试消失。

贯穿演进的三个问题

  1. 哪些流程保持专用？光栅化、纹理过滤、深度与混合等固定或可配置功能，在现代 GPU 仍能以高效率运行。
  2. 为何统一着色？顶点和像素工作的比例随场景变化。让通用着色资源承接多类任务，能减少专用核心闲置。wave/warp 成组执行，靠大量在途线程隐藏访存等待；分支发散会损失效率。
  3. 为何又增加专用单元？某些高频且计算密集的任务，例如光线相交和矩阵运算，适合额外加速。通用核心仍负责可编程的着色、计算和任务协调。
四节串起来

CPU 拆分并提交工作；空间变换决定几何覆盖哪些屏幕区域；渲染路径决定何时计算光和读写哪些缓冲；硬件结构则影响这些工作的吞吐与瓶颈。
